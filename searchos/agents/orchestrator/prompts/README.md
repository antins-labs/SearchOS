# Orchestrator 提示词

`../prompt.py` 按运行配置组装提示词。公共职责各出现一次；来源范围和任务约束决定采用哪些段落。

- `research.py`：规划、探索、任务派发与实时对话。
- `sources.py`：来源权限、本地资料定位及跨来源依赖。
- `tables.py`：表格建模、固定结构和选定单元格修复。
- `evidence.py`：证据判断、计算、引用与完成条件。

工具字段的类型、编码、默认值和校验规则由工具 schema 与 docstring 定义。提示词保留研究决策及必要例子，包括主键如何选择、属性归谁、如何界定成员，以及何时使用 `target_cells`、`max_searches`、`priority`。不能因为一条规则提到参数名，就把它当成接口说明删除。

启用编排技能时，其正文也会注入系统提示词。技能负责具体研究方法；参数契约仍由工具声明，任务范围服从当前运行配置。

本次提示词重构不修改任何 skill 的正文、元数据或配套资料。重构仅整理主提示词结构、合并重复指令、清理 legacy 表述；保留有效规则的适用条件、约束强度与必要例子。不得把“必须／禁止”改成建议，也不得以精简为由删除决策规则。

新增指令应说明当前任务的目标、动作或约束。历史故障及迁移背景保留在开发记录中。固定结构和定向修复通过选择对应段落表达，避免先注入通用流程，再用末尾规则覆盖。

普通模式注入建模规则；固定结构模式保留成员维护与字段口径，不注入建表、加列或 Explore 重设计建议；定向修复只注入选定单元格流程及公共证据、引用规则。追问单独强调复用现有数据。禁用计划工具时，规划仍在工作对话中进行。

原提示词的逐项对应、恢复项和未恢复原因见 [规则审计](AUDIT.md)。有效的否定约束（例如测量值不能作为主键、缺属性不能据此删行）属于设计规则，应保留。

配置组合由 `tests/test_orchestrator_dispatch_prompt.py` 验证；会话接线由初始探索策略、来源权限、定向修复及实时追问测试验证。离线测试覆盖组装与执行路径，提示词对真实模型的效果需要另行评估。
