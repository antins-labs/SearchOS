# v0.5 本地常驻运行与主机状态

更新：2026-10-15。当前针对个人 Mac；沿用单 API worker、同源网页和既有数据目录。

## 用户能看到什么

- 顶部连接标记、我的工作区卡片、定时计划提示使用同一份真实主机状态。
- “连接与设备”展示最后响应、本次服务运行时长、系统托管或手动启动、自动启动方式和防休眠配置。
- 前台每 10 秒检查一次，单次请求 6 秒超时。切回页面、网络恢复或点击重试时立即检查；超过 25 秒的旧成功状态不能继续显示在线。
- 网络中断显示“暂时无法连接”，不推断电脑一定关机；连接恢复与服务实例重启分别提示。断线时输入内容保留，不自动提交或重跑任务。
- 主机可连接但调度心跳过期、调度循环退出或最近一轮失败时，显示计划服务异常。
- 状态接口要求原有身份认证，不新增无鉴权管理端口。设备未绑定时仍走原登录入口。

## 本机运行方式

使用用户级 macOS LaunchAgent `com.searchos.personal`。**开机并登录当前用户后自动启动；锁屏不停止，注销账户会停止。** 不需要 sudo，也不是登录前启动的系统级 LaunchDaemon。机制依据 [Apple launchd 文档](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)。

LaunchAgent 托管一个轻量监督进程；监督进程分别运行 API、生产网页和可选防休眠进程。子进程退出后按退避自动重启，最长间隔 60 秒；监督进程本身退出由 launchd 重启。停止服务会先正常终止子进程，再为超时退出设置上限。默认 API 8000、网页 3100，均绑定 `127.0.0.1`，不设置公网入口。

防休眠使用系统 `caffeinate -s`，仅在接电时生效，不阻止屏幕熄灭；不会修改系统永久电源配置。拔电、合盖、手动睡眠、关机与注销不能视作服务持续可用。停止/卸载服务同时释放防休眠。笔记本长期运行应接电并保持通风。

进程自动恢复不代表当前研究能恢复：已启动但没有可确认结果的研究仍按中断处理；错过的计划继续沿用一小时补跑窗口。当前检测并提示调度卡住，但不会仅凭一次健康请求超时杀死仍在执行研究的进程。

## 管理方法

在仓库根目录执行，使用项目虚拟环境：

```bash
# 第一次安装或升级：先确认没有执行中任务并停止旧服务
.venv/bin/python web/service.py install

# 查看托管状态及网页/API 可达性
.venv/bin/python web/service.py status

# 停止 / 启动 / 重启
.venv/bin/python web/service.py stop
.venv/bin/python web/service.py start
.venv/bin/python web/service.py restart

# 永久取消自动启动并停止服务；保留配置、日志、计划与资料
.venv/bin/python web/service.py uninstall
```

`stop` 仅停止当前登录会话的服务，登录下次账户仍会加载；长期禁用请使用 `uninstall`。`install` 会构建生产网页，构建失败不会启用新服务。已加载时拒绝覆盖，端口被其他进程占用时拒绝抢占；不会自动终止未知进程。再次安装复用已有配置，不覆盖用户配置。

首次可使用 `--api-port 8000 --web-port 3100 --no-keep-awake` 自定义端口或关闭防休眠；已有安装修改下述 JSON 配置。网页反向代理目标在构建时固定，因此改 API 端口后必须停止、重新安装构建。普通模型配置继续使用原 `.env` 和网页设置，启动脚本不复制密钥。

开发与生产分开：安装器设置 `SF_NEXT_DIST_DIR=.next-service`，默认开发服务器仍使用 `.next`。常驻期间可以在另一网页端口进行前端开发；**不要再启动第二个使用同一助理数据目录的 API**。生产网页更新需要重新构建，不会因编辑源码自动热更新。升级步骤：确认任务空闲 → `stop` → 更新代码/依赖 → `install` → `status`。

## 文件与配置

| 文件 | 用途 |
| --- | --- |
| `web/service.py` | 安装、状态、停止、启动、卸载和进程监督 |
| `~/Library/LaunchAgents/com.searchos.personal.plist` | 当前用户的自动启动配置 |
| `~/Library/Application Support/SearchOS/service.json` | 固定仓库、Python、Node、PATH、端口和环境变量 |
| `~/Library/Application Support/SearchOS/logs/` | API、网页、监督与防休眠日志，各常规日志 2 MiB × 4 份；launcher.log 留存启动诊断 |
| `web/frontend/.next-service/` | 独立生产构建，已加入 Git 忽略 |

配置 JSON 中的 `environment` 可增加原有 `SF_PUBLIC_ORIGIN`、`SF_PUSH_CONTACT` 和数据目录等环境变量，修改后重启。端口/前端构建配置变更需重新安装构建。配置与 LaunchAgent 文件权限为 0600，日志目录仅当前用户访问。安装器固定解释器和 PATH，避免登录后台没有交互式终端环境导致找不到依赖。

不要移动仓库或删除虚拟环境、Node 和生产构建后期待服务继续运行；迁移路径后需要重新安装。位于 Downloads 的仓库若受到 macOS 隐私权限限制，先检查 launcher.log；不应通过关闭系统保护解决，可将项目与数据迁至合适的常驻目录后重新安装。
