## 产品范围

## 部署配置

| 配置 | 默认值与意义 |
| --- | --- |
| `SF_PUBLIC_ORIGIN` | 空：仅允许本机 API 访问。远程时填写唯一裸 HTTPS origin，例如 `https://search.example.com`，无路径/查询串 |
| `SF_API_PROXY` | Next 服务端转发目的地，默认 `http://127.0.0.1:8000`；支持同源 REST 与 WebSocket |
| `SF_ASSISTANT_ROOT` | 默认仓库 `.searchos/assistant`；保存 SQLite、管理员凭据、VAPID 私钥和单进程锁 |
| `SF_PUSH_CONTACT` | 配置管理员真实联系邮箱，格式 `mailto:you@example.com`；未配置时系统推送明确显示不可用 |
| `SF_PUSH_ALLOWED_HOSTS` | 可选，额外推送厂商域名精确名单；通常不需要设置 |
| `NEXT_PUBLIC_API_URL` | 同源模式应保持未设置。显式设置是既有开发兼容方式，不建议用于手机部署 |

基础 API 已能执行计划和保存消息。推送额外依赖可通过仓库虚拟环境安装 `pip install -e '.[mobile]'`；已在本机安装并在 `pyproject.toml` 声明。不要把数据库、admin-token 或 VAPID 私钥放进 frontend/public、workspace 文档目录或 Git。

操作顺序：

1. 使用一台持续运行的 SearchOS 主机。部署一个 API worker；多 worker 启动会被锁检查拒绝，避免内存研究会话分裂。
2. 选定允许使用的私网或公开网络方案，再配置 HTTPS 代理。代理将页面和 `/api/*` 放在同一 origin，支持 WebSocket Upgrade，并保留正确的 Host/Origin 信息。不要公开 API 8000 端口；保留回环绑定。
3. 在启动 API 的环境中设置 `SF_PUBLIC_ORIGIN`，需要推送时再设置 `SF_PUSH_CONTACT`。Next 的同源代理地址按实际本机端口设置。设置后重启服务，不使用开发热重载中断研究。
4. 在自己的管理员浏览器打开 HTTPS `/m`，选择“首次配置：管理员登录”，输入服务端私有目录的 `admin-token`。该文件首次启动自动生成，权限 0600；页面不会自动读取或展示它。
5. 在“连接与设备”生成配对码，手机打开同一个地址并输入。码有效 5 分钟、仅可用一次。新设备拥有此个人工作区全部操作权限，不是多用户隔离系统。
6. iPhone 通过 Safari 添加到主屏幕，从主屏幕打开后，在通知页主动启用系统通知，再点击发送测试通知。这里只验证推送，不执行研究。
7. 验收完成后启用需要的计划。系统休眠、停机和断网会影响执行与推送。

iPhone Web Push 需要支持的系统版本和主屏幕 Web App，并由用户操作请求授权；参见 [WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) 与 [Apple Web Push 文档](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)。公司是否允许这种访问与出站推送连接，需要按实际网络制度决定；代码不会自动作出该判断。

## 调度语义

- 使用 IANA 时区按墙上时间计算。夏令时不存在的时间跳过；重复时段一天执行一次。每日/每周只推进到未来下一次，避免积压后批量执行。
- 自动计划到点后启动；引擎正在研究时等待。晚于应执行时间一小时以内最多补跑一次，超过一小时生成跳过记录和异常消息。
- 单次计划执行时间过去后自动停用。立即执行独立排队，不改变周期；相同计划已有排队/执行记录时拒绝重复立即执行。
- 保存计划与立即执行接收幂等请求标识；修改/启停带版本，旧页面操作返回冲突，要求刷新后重试。
- 暂停只停止后续自动调度，不中断已经开始的研究。停止当前研究使用任务页的停止按钮。删除计划保留历史报告，并取消尚未启动的排队执行。
- 故障重启不自动重复已启动的研究。能确认本次已写出结果时收录报告，否则标为中断。尚未开始且没有会话的队列记录可以继续执行。
- 每次计划快照保存当时的指令、资料范围、深度和时间预算；后续修改不改变旧记录。模型与技能使用执行时的 SearchOS 配置。纯资料模式沿用独立文档研究策略，联网研究深度不适用，表单会禁用该选项；执行时间上限仍生效。
- 文档被删除或变为不可用时，沿用引擎的范围校验并报错，不静默扩大到整库。
- v0.3 浏览器草稿不会自动启用或迁移为付费执行计划；旧 localStorage 数据保留，需通过新计划表单明确保存。

## 主机生命周期与后续优化

手机是控制入口，SearchOS 主机负责保存、调度和执行。当前调度器位于 API 进程内，没有独立的云端执行服务。

| 场景 | 当前行为 |
| --- | --- |
| 手机锁屏、退出页面或离线 | 已交给服务端的任务继续；手机离线时不能下发新指令。系统通知是否送达还取决于手机网络、授权和推送服务 |
| 电脑关闭浏览器 | 不影响仍在运行的后端；网页服务仍需运行，供手机访问 |
| 电脑休眠、关机或 API 退出 | 无法按时执行；手机不能连接服务端。屏幕熄灭不等于系统休眠 |
| 主机断网 | 在线搜索、模型调用和推送受影响；是否失败取决于相应依赖和超时，不保证恢复后无缝续跑 |
| 服务重启 | 保留的数据可恢复；错过计划按一小时窗口补跑或跳过，已开始但未完成的研究按中断处理，已落盘结果可收录 |
| 手机绑定到期 | 当前设备登录有效 30 天，需重新登录或配对；后端计划不因手机登录到期而停止。配对码有效 5 分钟且仅可消费一次 |

普通服务重启不要求重新配对，前提是保留助理数据库、密钥和相同访问 origin，且设备登录未过期或撤销。更换访问域名需重新登录并重新订阅推送。服务端离线时，手机也无法读取此前未缓存的报告。

优化路线（第 1 步的常驻与主机状态已于 2026-10-15 实现，详情见 10；备份与后续迁移仍待实现）：

1. **本地常驻运行**：已实现生产构建、登录自动启动、进程退出重启、接电防休眠、手机心跳与恢复提示。备份恢复和磁盘容量管理待补充。自动重启进程不等于恢复执行中的研究。
2. **迁到常开主机**：优先用于个人长期使用。将网页、API、调度器和数据一起迁至个人常开主机或获准使用的服务器，开发电脑即可关机。保留单 API worker；迁移时先停旧执行端，避免两台主机重复调度。迁移助理私有目录、`SF_WORKSPACE_ROOT`（默认 `searchos_workspace`）、`SF_LOCAL_DATA_ROOT`（默认 `knowledge_base`）、模型配置、凭据与自定义技能，完成恢复验证后再启用计划。不能只复制代码。
3. **按需拆分调度与执行**：长期扩展再引入持久任务队列、独立 worker、心跳、租约、幂等和取消协议，区分可安全重试的步骤与模型调用；控制服务可保存离线期间下发的指令，等待执行端上线。
4. **可选云端与本地协作**：允许上云的联网任务交给常开远端执行，私有资料任务留在本地 worker。本地 worker 通过允许的出站连接领任务；它离线时相关任务只能等待。中转和 VPN 只解决连接，不会让关机电脑执行任务。公司资料与公司电脑继续受实际网络及数据制度约束。

个人阶段优先推进第 1、2 步，暂不引入多执行端复杂度。手机已展示主机连接状态、最后响应、运行时长和重启提醒；设备登录剩余有效期的汇总提示待优化。

## 通知、报告与数据

SQLite 保存 plans/runs/reports/notifications/devices/subscriptions/preferences/outbox 等对象，数据库由应用独立维护。报告和消息保留至后续增加清理功能或管理员备份维护，当前没有自动删除策略。

完成报告与异常消息在同一事务中提交，通知按 run 去重；报告内容是完成时的快照。即时任务、资料任务与定时任务使用同一结果收录逻辑。快速连续追问会先收录前一轮，再替换执行会话。

系统推送仅含通用提醒、随机事件标识和站内跳转路径，不含问题正文、文档名称或报告内容。通知仍经浏览器厂商的推送服务出站发送，不能理解为全程不出网。

推送失败只重试投递，最多 5 次，退避最多一小时；不会重跑研究。免打扰期间延迟投递；关闭对应提醒的设备取消该投递。404/410 订阅会被清理。投递状态“已交给推送服务”不表示用户已看到。宕机在发送成功与状态落盘之间可能重复投递，浏览器 tag 会合并相同事件。

报告正文通过认证后读取。Service Worker 不安装离线缓存；通知 URL 限定同源 `/m`，拒绝外部跳转。

## 访问控制

所有既有 `/api/*` REST、文件下载和 WebSocket 都经过统一校验，不只保护新增接口。远程设备令牌存为 HttpOnly、Secure、SameSite=Strict Cookie，数据库只存哈希，有效 30 天；页面重新登录后恢复原有报告深链接。

配对、管理员登录有独立速率限制；修改请求同时检查 Origin 与自定义请求头。撤销设备会阻止新请求，并在约 1 秒内关闭已有 WebSocket。下载响应不缓存，附带 sandbox CSP，避免上传的 HTML 取得应用的同源执行权限。

本机免登录只允许回环来源和本机 Host；未配置远程 origin 不会自动开放 LAN 访问。单用户绑定设备是完全可信设备，包含设置操作权限，不应将配对码交给他人使用。
