# SearchOS iPhone 方向原型 · v0.6.3

> 视觉与文案规范已由 [13 · v0.7 墨蓝简报](13-ink-mobile-design.md) 替代。本文件保留 v0.6.x 的设计迭代与流程背景。

更新：2026-10-19。状态：设计提案 / 可点击原型，待用户评审。用户已确认原生 iPhone 风格，具体新布局尚未确认。正式 `/m` 功能状态仍以 09、10 为准。

## 产品承诺

打开手机，交办一个搜索任务；离开后等待完成提醒；返回时可以快速读懂结果，并继续追问或设为周期任务。

## 信息架构与主要路径

底部保持「助理 / 任务 / 我的」。消息为顶部入口；报告、执行进展为详情页；创建、选择和编辑采用聚焦任务的独立页面。

| 页面 | 用户要完成什么 | 主要操作与退出方式 |
| --- | --- | --- |
| 助理 | 交办、查看刚完成的结果 | 输入任务、打开最近报告；进入编辑后聚焦输入 |
| 交办任务 | 写清目标和资料范围 | 选择资料、来源、任务选项；显式发送；返回保留草稿 |
| 资料选择 | 确认这次能用哪些文档 | 搜索、勾选、确认；取消不改之前选择；不可用文档不允许选择 |
| 执行进度 | 知道正在做什么 | 阶段说明、补充要求、停止；允许离开；不虚构百分比 |
| 任务 | 找到某次执行 | 状态筛选、搜索、打开报告或执行详情 |
| 定时计划 | 管理持续委托 | 查看下次执行、编辑、暂停/恢复；与执行记录分开 |
| 计划编辑 | 设置内容、频率和时间 | 修改名称、目标、频率、时间；确认后保存；显示时区 |
| 报告摘要 | 快速判断结果是否值得读 | 默认前三条、展开全部 16 条、逐条阅读、完整报告 |
| 条目详情 | 理解一条发现 | 事件、意义、来源；上一条/下一条；返回保留展开状态 |
| 完整报告 | 连续阅读整体结论 | 清晰正文、来源、底部轻量追问；不固定大输入框 |
| 消息 | 接收完成与异常提醒 | 未读标记，点击直达报告或异常；返回仍在消息页 |
| 我的 | 管理连接、资料与偏好 | 分组列表，不做数据仪表盘 |
| 主机与连接 | 理解主机可用性 | 连接状态、最后响应；未绑定时填写地址/配对码；失效时重新连接 |
| 通知偏好 | 控制何时提醒 | 完成/异常提醒、免打扰；未授权、已授权、拒绝的独立状态 |

路径 A：助理 → 交办 → 资料选择 → 确认 → 发送 → 执行进度 → 报告摘要 → 条目 → 完整报告。

路径 B：任务 → 定时计划 → 编辑 → 保存 → 暂停/恢复 → 执行记录。

路径 C：消息 → 对应报告 → 继续追问；消息中的失败任务 → 异常说明 → 重试。

路径 D：主机离线 → 输入保留为草稿 → 连接恢复 → 用户主动发送。

## 视觉与组件规范

- 画板基准 390×844；核查 320px、430px 和桌面评审视图。全屏体验模式在窄屏隐藏评审说明。
- 系统字体 `-apple-system / BlinkMacSystemFont / PingFang SC`；首页标题 27、列表大标题 32、报告标题 29、正文 16–17、辅助 12–13、导航 11–12。
- 页面背景浅雾蓝 `#EDF3FA`，主要卡片白色，次级卡片与图标小框为低饱和灰蓝；正文 `#25384F`，辅助文字 `#667A92`，操作色 `#456B98`。既有品牌标志保持原色。
- 保留明确的容器：输入框、快捷建议、进行中任务、执行记录、资料项、计划、消息均有边框与圆角。主要卡片圆角 16–20，小框 9–12，统一细边框和低透明度轻阴影。
- 报告采用白色摘要总卡片，内含浅蓝条目卡片 `#E9F1FC`；序号使用小框。分类不随机配色，层级通过背景、边框、间距和字体区分。
- 功能图标保留，并恢复统一灰蓝小底框；不使用星芒与鲜艳装饰色。任务状态仍有文字，避免仅靠颜色识别。
- 按钮和列表点击区域至少 44px；主要按钮 50–52px。正文长标题换行，不强迫单行省略；来源以名称/域名呈现。
- 原型为 HTML 对 iPhone 交互的表达，不等于原生 SwiftUI、真实系统键盘或系统权限弹窗。

## v0.6.3 蓝色系修订（当前评审版）

用户进一步明确：整体要有蓝色倾向，但不要太亮。保留 v0.6.2 的全部卡片结构，只调整色彩。

- 页面底色：浅雾蓝 `#EDF3FA`；主文字：深蓝灰 `#25384F`。
- 主按钮与操作：沉稳灰蓝 `#456B98`，发送按钮 `#45658E`。
- 首页简报卡片：淡蓝 `#E5EEFB`；报告条目：浅蓝 `#E9F1FC`；其他主卡片保留白色。
- 图标小框、筛选选中态、工具按钮同步蓝色倾向，边框统一为低对比蓝灰。品牌原图保持原色。
- 原型总览背景同步为灰蓝；页面结构和交互不变。

## v0.6.2 卡片与色调修订

用户澄清：需要卡片与小框，上一轮去掉过多容器导致粗糙；应保留层次，降低颜色饱和度。

- 恢复首页快捷建议小框、资料/范围工具按钮底框、进行中任务卡片与功能图标底框。
- 执行记录、资料选择与消息恢复独立卡片；选中资料以浅灰蓝底和稍深边框标记。
- 交办页文字输入有完整白色容器；执行阶段放入白色卡片；计划与设置组保留圆角边框。
- 报告摘要恢复总卡片及条目小卡片，保留展开与逐条阅读操作。
- 主色采用低饱和灰蓝，完成状态采用灰绿；通过细边框、少量阴影和留白建立层级。
- 本机检查：390px 首页、任务与报告视觉核查；320px 报告及资料选择无横向溢出；摘要展开 16 条、进入条目并返回、追问并选择资料已走通；未记录浏览器脚本错误。
- 当前截图：[首页](previews/v6-cards-home.png)、[任务](previews/v6-cards-tasks.png)、[报告](previews/v6-cards-report.png)。

## v0.6.1 视觉修订

用户反馈：小图标和整体表达带有过强的 AI 模板感；左上角应使用既有 SearchOS 标志。

- 品牌：采用仓库现有的蓝色「S＋放大镜」图形，直接复制 `web/frontend/public/searchos-mark.png` 到原型 `assets/searchos-mark.png`，不重新绘制或修改图片。仓库品牌原稿位于 `assets/searchos_logo_icon.png` / `assets/searchos_logo.png`；[GitHub 项目](https://github.com/antins-labs/SearchOS) 与[项目主页](https://antins-labs.github.io/SearchOS/)为核对入口。手机顶部、评审台、总览页、个人工作空间与 favicon 使用同一素材。
- 首页：标题改为「今天想了解什么？」，结果区改为「最近结果」；去掉渐变和宣传式大标题，输入、结果、进行中任务三个层级依次排列。
- 任务与设置：执行记录以标题、状态、时间对齐；进度页用小状态标记和时间线；设置项去掉重复的装饰图标。
- 报告：摘要头以标题、数量和展开箭头表达操作；条目用统一底色、序号、分类、标题与来源排版。保留摘要展开 16 条、逐条阅读、完整报告与追问路径。
- 文案：删减「让你轻松掌握」「为你准备」等泛化表达；通知、我的、计划等页面使用直接的名称和说明。

本次仍为独立原型修订，尚未替换正式 `/m`。

## 状态覆盖与范围

评审侧栏可切换正常、首次使用、主机离线、执行失败与通知未开启。原型中的任务、文档、新闻条目和消息均为虚构示例；不请求后端、不调用模型、不读取本地知识库、不申请系统通知权限。状态仅在当前页面内存中变化，刷新复位。

可以体验：输入/保留草稿、选择资料（取消/确认）、来源范围、发送后的进度、演示完成、报告展开/条目/返回、执行筛选与搜索、计划编辑/启停、未读消息、连接与通知状态。

不在本轮证明范围：真实搜索、真实调度、实际配对、后台推送、Safari 系统键盘与安全区实机表现。语音、跨任务自动审批、多主机调度与云端离线队列不加入这版。

## 评审清单

1. 首页是否一眼知道如何交办？输入和最近结果是否主次清楚？
2. 资料选择能否确认范围，取消是否保留之前已选？
3. 任务、计划、报告三个对象是否易于区分？
4. 报告是否比对话适合阅读？返回是否保留列表展开和位置？
5. 离线、空状态和失败是否明确说明下一步？
6. 通知是否直达结果，且无需打开所有日志？

通过本轮评审后，再把页面结构和组件规范接入现有 `/m`。后端接口复用情况应逐项核对，不将原型状态直接替换真实状态。

## 本机验证记录（2026-10-19）

- 浏览器实际走通：建议填入 → 选两份资料 → 确认；重新选择并取消后仍保留原两份；发送进入进度页；补充要求追加到原任务。
- 走通完成演示 → 摘要 → 展开 16 条 → 第 16 条 → 上一条 → 返回；返回时仍有 16 条，保留列表滚动位置；完整报告 → 追问预填。
- 走通计划暂停、编辑名称/每周频率/时间并保存；离线输入保存为草稿；首次使用从草稿进入连接；通知未授权 → 演示拒绝 → 开启方法；失败任务 → 重试。
- 320px 报告、390px 资料选择、430px 首页无整页或主内容横向溢出；桌面评审台与独立手机模式均可访问。浏览器检查未发现脚本错误；JavaScript 语法检查和差异空白检查通过。
- 截图：[报告](previews/v6-report.png)、[资料选择](previews/v6-materials.png)。本轮仅原型交互验证，不是后端集成或 iPhone 实机验收。

本机预览：在仓库根目录运行 `python3 -m http.server 3102 --bind 127.0.0.1 --directory workspace/mobile-assistant/prototype-v6`，访问 `http://127.0.0.1:3102/`。也可直接用浏览器打开 `prototype-v6/index.html`；没有构建依赖。仅在当前电脑预览，未建立远程入口。
